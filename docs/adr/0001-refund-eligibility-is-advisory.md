# Refund Eligibility is advisory, not binding

Refund Eligibility is shown to the Instructor or Admin deciding a Refund Request, but it does not stop them from Approving an ineligible request or Declining an eligible one. Every Refund Request is reviewed by hand, and the rules (window, watch time, completion, team seat) can't see every legitimate case. Making eligibility binding would turn a person's judgement into a checkbox. The rules *are* binding when a learner makes a Refund Request: the server refuses requests the rules don't allow.

## Consequences

- Eligibility is worked out at decision time, not stored when the request is made. The Refund Window is measured from the day the Refund Request was made. Watching and completion are counted up to the decision, so a learner who keeps watching while the request is Requested can become ineligible.
- Don't "fix" the Approve action to reject ineligible requests. That is deliberate.
